⚡ EZ Encoding — 7-Stage Pipeline

EZ Encoding transforms raw bytes through 7 successive stages, each reducing the output size.
Every stage is fully reversible — decoding runs all 7 stages in reverse order.

STEP 1 ⚙ Raw Binary — each byte → 8-bit string
Every input byte is written as its 8-bit binary representation.
Input: "Hi" = bytes 72, 105
Binary: 01001000 01101001
STEP 2 🔤 Bit-pairs → ABCD alphabet 00=A 01=B 10=C 11=D
Each pair of bits is mapped to one of four letters A–D. This converts the binary stream into a 4-symbol alphabet stream (4× the original byte count).
Binary: 01 00 10 00 → ABCD: B A C A = BACA
Mapping: 00→A   01→B   10→C   11→D
STEP 3 🔡 ABCD-pairs → Single Letter AA=E AB=F … DD=T
Consecutive pairs of ABCD letters are merged into a single letter from E to T (16 letters total). This halves the length — 2 chars become 1 char. The resulting string contains only letters E–T.
ABCD: BA CA → Letters: I M
Full table: AA=E AB=F AC=G AD=H | BA=I BB=J BC=K BD=L | CA=M CB=N CC=O CD=P | DA=Q DB=R DC=S DD=T
STEP 4 🔤 Top-26 Pattern Substitution — frequent patterns (len 2–5) → a–z
Scans the E-T letter string and counts every overlapping sub-pattern of length 2 to 5. Each pattern is scored by occurrences × (length – 1), measuring total chars saved. The 26 highest-scoring patterns are assigned lowercase letters a–z. A map header like [aGEH,bKN,cMNT…] is prepended. At each position the longest matching pattern wins (greedy left-to-right).
Letter string: GEHGEHKN GEHKN (GEH appears 3×, KN 2×)
Map: [aGEH,bKN]   After subst.: aab ab
GEH (len 3, 3×) scores 3×2=6 > KN (len 2, 2×) scores 2×1=2 → a assigned to GEH
STEP 5 🔣 Double-letter pairs → Compact Symbols
When two identical letters appear together (like EE, FF, TT…), they are replaced by a single printable symbol. 26 symbol mappings cover all letter doubles. This can only improve or maintain output length.
EE→'   FF→{   GG→(   HH→:   KK→\`   TT→/
Input: EEKK → Output: '\` (4 chars → 2 chars)
STEP 6 📦 Run-Length Encoding — repeated identical chars → compact token
The final stage scans the output for runs of repeated identical characters OR 2-character patterns. Any run that can be represented more compactly is replaced by the token #pat*n#, where pat is the 1- or 2-char repeating unit and n is its count. The algorithm tries both pattern sizes at each position and picks whichever saves the most characters. The # delimiter is safe — it never appears in earlier stages. Compression is only applied when the token is strictly shorter than the run.
1-char run: 1111111111111111111111 (22×) → #1*22# (saves 16 chars)
2-char bigram: efefefefefefefefefef (10× "ef") → #ef*10# (saves 13 chars)

Thresholds:
 1-char: benefit when run ≥ 8 identical chars (e.g. aaaaaaaa → #a*8#)
 2-char: benefit when ≥ 4 repetitions (e.g. abababab → #ab*4#)
🔄 Decoding — All 5 Steps in Reverse
6. RLE decode: #x*n# → x repeated n times
5. Symbol decode: compact symbol → 2-letter pair ('→EE, etc.)
4. Pattern decode: parse map header, expand a–z → E-T patterns
3. Letter decode: each E–T letter → 2 ABCD chars
2. ABCD decode: each ABCD char → 2 bits (A=00 B=01 C=10 D=11)
1. Bytes: group 8 bits → original byte ✓
